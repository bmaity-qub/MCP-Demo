# MCP Live Demo — Document Search + Grounded Answers

This is the demo used in the KT's "Demo setup" and live-demo sections.

## Why Groq

Groq provides cloud access to LLMs through an API, so the final answer generation does not depend on the laptop's hardware.

Retrieval (FAISS + `sentence-transformers`) stays fully local and free, same as before. Only the final answer-generation step calls out to Groq.

## What it demonstrates

1. An **MCP server** (`server.py`) that indexes a few `.txt` files with FAISS and exposes one tool: `search_documents(query, top_k)`.

2. An **MCP client** (`client.py`) that:

   * connects to the server over stdio
   * discovers the tool at runtime
   * calls the tool with the user's question
   * sends the retrieved chunks to Groq to produce a grounded answer

## Setup (one-time, ~5 minutes)

### 1. Install dependencies

```bash
cd mcp-demo-openrouter

uv venv

source .venv/bin/activate        # Windows: .venv\Scripts\activate

uv pip install -r requirements.txt
```

### 2. Get a Groq API key

1. Go to the Groq console.
2. Sign in or create an account.
3. Create an API key.

### 3. Put the key in `.env` — not in your terminal

This is the safe way to handle the key, especially if you're sharing your screen during the demo.

```bash
cp .env.example .env
```

Open `.env` and add:

```text
GROQ_API_KEY=your-real-key-here
```

`.env` is already listed in `.gitignore`, so the key will not be committed or pushed accidentally. `client.py` loads it automatically via `python-dotenv`.

## Running the demo

```bash
python client.py "How does MCP reduce integration maintenance?"
```

Expected output:

→ tools/list

Try other questions live, e.g.:

```bash

```

## Presenting this live

1. Show the `docs/` folder briefly — "just three plain text files, standing in for internal knowledge."

2. Run `python client.py "<question>"` live.

3. Point out `tools/list` discovering the tool before you've told the client anything about it — that's the MCP contract in action.

4. Point out the retrieved chunks — that's the RAG half.

5. Point out the grounded answer generated by the LLM.

## Troubleshooting

| Symptom                       | Fix                                                                           |
| ----------------------------- | ----------------------------------------------------------------------------- |
| `GROQ_API_KEY is not set`     | Confirm `.env` exists and contains the API key                                |
| `Groq error: ...`             | Check the error text and confirm the API key and selected model are available |
| `ModuleNotFoundError: dotenv` | `uv pip install -r requirements.txt` inside the venv                          |
| Slow first run                | The embedding model downloads on first use — run once before presenting       |
| Irrelevant search results     | Add more/better docs, or lower `top_k` in `server.py`                         |
|                               |                                                                               |
